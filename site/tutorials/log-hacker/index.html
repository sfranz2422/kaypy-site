Building Log Hacker

Play it first → You have broken into a server and you are reading its log: one line for every time somebody tried to log in. Somewhere in it, somebody typed their password into the box where their name should go, and the server wrote it down. The real users are listed on the right. Click the FAILED line whose name isn't on the list before the trace reaches 100%. Every server is faster than the last.

This is how it was built, a step at a time. Every numbered step below is a whole program: copy it into the playground, press Run, and it works. Each step is the one before it with something added, so you can build the game the way it was built. Then break something on purpose and see what changes. That teaches you more than reading does.

There is nothing clever in it. No list comprehensions, no tricks, and every kaypy function it uses is on the API page. There are no pictures at all, only words, and four sounds from the playground.

It is the game for Lesson 9 — Files, and it comes after Goblin Hit. It uses the same pieces: functions, global, wait(), onClick with isHovering(), and a scene. If any of those are new, build Goblin Hit first. After this one, try Paddle Ball.

The one big idea: write it, close it, read it back

A file is text with a name, kept somewhere other than your program. You get at it in three moves: open() it, use it, close() it. Open it with "w" and you can write in it; open it with "r" and you can read it.

A real hacker would find the files already on the server. This game has no server, so it makes its own: it writes users.txt and log.txt first, then reads them back exactly as it would read any file. It writes new ones for every server, so the log is never the same twice.

Run it on your own computer and the two files appear in the folder your program runs in, where you can open them and look. In the playground they are just as real, but they live inside the page, and they are gone when you reload it.

Step 1 — a file of users

Write four names into a file, read them back, and put them on the screen.

from kaypy import *

kaypy(width=800, height=600, background=[8, 14, 10])

GREEN = rgb(90, 230, 120)
DIM = rgb(50, 110, 65)

# Write the file. "w" means write: it makes users.txt, or empties it if
# it is already there. "\n" is the end of a line -- write() does not add
# one for you.
users_file = open("users.txt", "w")
users_file.write("ada\n")
users_file.write("zoe\n")
users_file.write("max\n")
users_file.write("sam\n")
users_file.close()

# Read it back. "r" means read. Each time round the for loop, line is the
# next line of the file, "\n" and all, and strip() takes the "\n" off.
users = []
users_file = open("users.txt", "r")
for line in users_file:
    users.append(line.strip())
users_file.close()

# The users, down the right-hand side.
add([text("users.txt", size=20), pos(600, 100), color(DIM)])
y = 130
for name in users:
    add([text(name, size=26), pos(610, y), color(GREEN)])
    y = y + 32
  • open("users.txt", "w") makes the file and hands it back, ready to write in. "w" means write. If there is already a users.txt, it is emptied first. The variable users_file is how the rest of the program gets at it.
  • write() puts exactly what you give it into the file, and nothing else. It doesn't start a new line for you. "\n" is the end of a line, so "ada\n" is "ada" and then a new line.
  • close() says you have finished with it. Until then, what you wrote may not be in the file yet. The second Break it below shows that.
  • open("users.txt", "r") opens it again to read. for line in users_file goes round once for each line in the file, top to bottom, and each time line is the next one.
  • line still has its "\n" on the end. The first time round it is "ada\n", not "ada". strip() takes it off, along with any spaces at either end. Step 4 shows what goes wrong if you forget.

Break it. Take the \n out of all four write() lines. There is no error, but there is only one user now, and it is called adazoemaxsam.

The four names went into the file one after another with nothing between them, so the file is one line long. Reading it back, the loop finds one line.

Break it. Put the \ns back, and take out the first users_file.close(), the one after the writing. There is no error this time either, but no users at all. The list under users.txt is empty.

Python doesn't write to the file the moment you call write(). It saves it up and writes it all at once, and close() is what makes it do that. Here the file is read before it was ever closed, so it is still empty. Close a file as soon as you have finished with it.

Step 2 — a log to read

Now the program makes up a server. It picks four users at random and writes them, then writes a log of sixteen logins and reads it back onto the screen.

from kaypy import *

kaypy(width=800, height=600, background=[8, 14, 10])

GREEN = rgb(90, 230, 120)
DIM = rgb(50, 110, 65)

NAMES = ["ada", "max", "zoe", "leo", "mia", "raj",
         "olivia", "lucas", "amara", "kenji", "sofia", "mateo"]


def two_digits(number):
    if number < 10:
        return "0" + str(number)
    return str(number)


def clock(minutes):
    # 75 minutes after midnight is 01:15. // is how many whole hours, and
    # % is the minutes left over.
    hours = minutes // 60 % 24
    return two_digits(hours) + ":" + two_digits(minutes % 60)


def write_files(how_many_users, how_many_lines):
    # Pick the users. A name that is already picked is skipped, so the
    # loop goes round until there are enough different ones.
    users = []
    while len(users) < how_many_users:
        name = choose(NAMES)
        if name not in users:
            users.append(name)

    users_file = open("users.txt", "w")
    for name in users:
        users_file.write(name + "\n")
    users_file.close()

    # The log: one login on each line, when, who, and whether it worked,
    # with commas between them -- 01:07,zoe,ok
    log_file = open("log.txt", "w")
    minutes = randi(0, 300)
    for number in range(how_many_lines):
        minutes = minutes + randi(1, 9)
        name = choose(users)
        if chance(0.3):
            result = "failed"
        else:
            result = "ok"
        log_file.write(clock(minutes) + "," + name + "," + result + "\n")
    log_file.close()


def read_users():
    users = []
    users_file = open("users.txt", "r")
    for line in users_file:
        users.append(line.strip())
    users_file.close()
    return users


write_files(4, 16)
users = read_users()

add([text("users.txt", size=20), pos(600, 100), color(DIM)])
y = 130
for name in users:
    add([text(name, size=26), pos(610, y), color(GREEN)])
    y = y + 32

# Read the log, and put each line on the screen. split(",") cuts a line
# up at every comma: "01:07,zoe,ok" becomes ["01:07", "zoe", "ok"].
add([text("log.txt", size=20), pos(20, 72), color(DIM)])
y = 100
log_file = open("log.txt", "r")
for line in log_file:
    parts = line.strip().split(",")
    add([text(parts[0], size=22), pos(20, y), color(DIM)])
    add([text(parts[1], size=22), pos(110, y), color(GREEN)])
    if parts[2] == "failed":
        add([text("FAILED", size=22), pos(310, y), color(RED)])
    else:
        add([text("ok", size=22), pos(310, y), color(GREEN)])
    y = y + 28
log_file.close()
  • Every line of the log is one login, with three parts and a comma between each: when it was, who it was, and whether it worked. 01:07,zoe,ok. That is how the program writes it, so that is how it can read it back.
  • write_files picks the users with a while loop. choose(NAMES) picks a name, and it only goes on the list if it isn't on it already. A for loop would go round exactly four times and could pick the same name twice. The while loop goes round until there are four different ones.
  • The times go up a few minutes at a time: randi(1, 9) is a whole number from 1 to 9. clock() turns minutes into a time. minutes // 60 is how many whole hours there are, and minutes % 60 is the minutes left over, so 75 minutes is 01:15. two_digits() puts a 0 in front of a number less than ten, so it says 01 rather than 1.
  • chance(0.3) is True three times in ten, so about a third of the logins fail.
  • split(",") cuts a line up at every comma and gives back a list. "01:07,zoe,ok" becomes ["01:07", "zoe", "ok"], so parts[0] is the time, parts[1] the name and parts[2] whether it worked.

Break it. Change split(",") to split(), with nothing in the brackets. It stops straight away with

IndexError: list index out of range

on the line that uses parts[1]. With nothing in the brackets, split() cuts at spaces, and there are no spaces in 01:07,zoe,ok. So it comes back in one piece, ["01:07,zoe,ok"], and there is no parts[1]. "Out of range" means you asked a list for a position it doesn't have.

Step 3 — the log goes past

A real log doesn't sit still. Now the lines come in at the bottom one at a time and move up, and when the log runs out it starts again from the top.

from kaypy import *

kaypy(width=800, height=600, background=[8, 14, 10])

GREEN = rgb(90, 230, 120)
DIM = rgb(50, 110, 65)

SCROLL = 40       # how fast the log goes past, in pixels a second
ROW = 28          # how tall one line of the log is, in pixels
LOG_TOP = 90      # a line that goes above this has gone
LOG_BOTTOM = 560  # ...and a new one comes in here

NAMES = ["ada", "max", "zoe", "leo", "mia", "raj",
         "olivia", "lucas", "amara", "kenji", "sofia", "mateo"]


def two_digits(number):
    if number < 10:
        return "0" + str(number)
    return str(number)

    # % is the minutes left over.
    hours = minutes // 60 % 24
    return two_digits(hours) + ":" + two_digits(minutes % 60)

    # loop goes round until there are enough different ones.

    users_file.close()

    # with commas between them -- 01:07,zoe,ok

        name = choose(users)
        if chance(0.3):
            result = "failed"
        else:
            result = "ok"
        log_file.write(clock(minutes) + "," + name + "," + result + "\n")
    log_file.close()


def read_users():
    users = []
    users_file = open("users.txt", "r")
    for line in users_file:
        users.append(line.strip())
    users_file.close()

write_files(4, 16)
users = read_users()

add([text("users.txt", size=20), pos(600, 100), color(DIM)])
y = 130
for name in users:
    add([text(name, size=26), pos(610, y), color(GREEN)])
    y = y + 32

add([text("log.txt", size=20), pos(20, 72), color(DIM), z(10)])

# Two dark bands over the top and bottom of the log, so lines slide in
# and out of sight behind them.
add([rect(800, LOG_TOP), pos(0, 0), color(8, 14, 10), z(5)])
add([rect(560, 600 - LOG_BOTTOM - ROW), pos(0, LOG_BOTTOM + ROW),
     color(8, 14, 10), z(5)])


def show(when, name, result):
    # One line of the log: a dark strip at the bottom, which moves up.
    # The words are its children, so they move with it.
    row = add([rect(540, ROW - 2), pos(10, LOG_BOTTOM), color(8, 14, 10),
               "row"])
    row.add([text(when, size=22), pos(10, 4), color(DIM)])
    row.add([text(name, size=22), pos(100, 4), color(GREEN)])
    if result == "failed":
        row.add([text("FAILED", size=22), pos(300, 4), color(RED)])
    else:
        row.add([text("ok", size=22), pos(300, 4), color(GREEN)])


# The log is read one line at a time, with readline(). The file stays
# open in between, and remembers where it got to, so each readline()
# hands over the line after the last one.
log_file = open("log.txt", "r")


def next_line():
    global log_file

    line = log_file.readline()

    # At the end of the file there is nothing left, and readline() gives
    # back "". Close it, open it again, and start from the top.
    if line == "":
        log_file.close()
        log_file = open("log.txt", "r")
        row = add([rect(540, ROW - 2), pos(10, LOG_BOTTOM),
                   color(8, 14, 10), "row"])
        row.add([text("----- end of log.txt, reading it again", size=22),
                 pos(10, 4), color(DIM)])
        wait(ROW / SCROLL, next_line)
        return

    parts = line.strip().split(",")
    show(parts[0], parts[1], parts[2])

    # The next line once this one has moved up out of its way.
    wait(ROW / SCROLL, next_line)


next_line()


# Every row moves up, and one that has gone past the top is gone.
@onUpdate("row")
def move_up(row):
    row.pos.y = row.pos.y - SCROLL * dt()
    if row.pos.y < LOG_TOP - ROW:
        row.destroy()
  • readline() reads one line, and only one. The file stays open, and remembers how far it has got, so the next readline() gives back the line after that. That is how the game can show one line now and the next a moment later.
  • At the end of the file, readline() gives back "", an empty string, because there is nothing left. That's how you know the file has run out. Even a blank line in the middle of a file is "\n", so "" only ever means the end.
  • To start again from the top, the program closes the file and opens it again. A newly opened file always starts at its first line. A row saying so goes past first.
  • Each line is a dark strip, a rect(), and the words are its children, added with row.add(). A child's pos() is measured from its parent, and it moves when the parent moves, so moving the strip moves all three words.
  • wait(ROW / SCROLL, next_line) asks for the next line once this one has moved up out of its way. A line is 28 pixels tall and the log moves 40 pixels a second, so that is every 0.7 seconds.
  • The two dark bands at z(5) are drawn over the lines at the top and bottom, so the lines slide out from behind one and away behind the other.

Break it. Take out the whole if line == "": part, down to its return. The log goes past as before, until about eleven seconds in, when all sixteen lines have been read. Then it stops with

IndexError: list index out of range

on show(parts[0], parts[1], parts[2]). At the end of the file line is "", and splitting nothing gives a list with one empty thing in it, [""]. There is no parts[1]. Reading a file one line at a time, you always have to check for the end.

Step 4 — the password, and clicking

Now somebody slips up. Somewhere in the log is a password where a name should be. Find it and click it.

from kaypy import *

kaypy(width=800, height=600, background=[8, 14, 10])

GREEN = rgb(90, 230, 120)
DIM = rgb(50, 110, 65)

SCROLL = 40       # how fast the log goes past, in pixels a second
ROW = 28          # how tall one line of the log is, in pixels
LOG_TOP = 90      # a line that goes above this has gone
LOG_BOTTOM = 560  # ...and a new one comes in here

NAMES = ["ada", "max", "zoe", "leo", "mia", "raj",
         "olivia", "lucas", "amara", "kenji", "sofia", "mateo"]

# Real passwords that real people use. A lot of them are names.
PASSWORDS = ["dragon", "qwerty", "letmein", "monkey", "sunshine",
             "football", "shadow", "jordan", "michael", "jessica",
             "charlie", "ashley", "daniel", "thomas", "maggie", "taylor"]


def two_digits(number):
    if number < 10:
        return "0" + str(number)
    return str(number)


def clock(minutes):
    # 75 minutes after midnight is 01:15. // is how many whole hours, and
    # % is the minutes left over.
    hours = minutes // 60 % 24
    return two_digits(hours) + ":" + two_digits(minutes % 60)


def write_files(how_many_users, how_many_lines):
    # Pick the users. A name that is already picked is skipped, so the
    # loop goes round until there are enough different ones.
    users = []
    while len(users) < how_many_users:
        name = choose(NAMES)
        if name not in users:
            users.append(name)

    users_file = open("users.txt", "w")
    for name in users:
        users_file.write(name + "\n")
    users_file.close()

    # The line where somebody slips up. Not one of the first few, so you
    # have read a little of the log before it comes.
    slip = randi(4, how_many_lines - 1)

    # The log: one login on each line, when, who, and whether it worked,
    # with commas between them -- 01:07,zoe,ok
    log_file = open("log.txt", "w")
    minutes = randi(0, 300)
    for number in range(how_many_lines):
        minutes = minutes + randi(1, 9)
        when = clock(minutes)

        if number == slip:
            # A password where the name should be, which fails -- and then
            # the same person, a moment later, getting it right.
            victim = choose(users)
            log_file.write(when + "," + choose(PASSWORDS) + ",failed\n")
            log_file.write(when + "," + victim + ",ok\n")
        else:
            name = choose(users)
            if chance(0.3):
                result = "failed"
            else:
                result = "ok"
            log_file.write(when + "," + name + "," + result + "\n")

    log_file.close()


def read_users():
    users = []
    users_file = open("users.txt", "r")
    for line in users_file:
        users.append(line.strip())
    users_file.close()
    return users


write_files(4, 16)
users = read_users()

add([text("users.txt", size=20), pos(600, 100), color(DIM)])
y = 130
for name in users:
    add([text(name, size=26), pos(610, y), color(GREEN)])
    y = y + 32

add([text("log.txt", size=20), pos(20, 72), color(DIM), z(10)])

add([rect(560, 600 - LOG_BOTTOM - ROW), pos(0, LOG_BOTTOM + ROW),
     color(8, 14, 10), z(5)])


message = add([text("", size=40), pos(280, 300), anchor("center"),
               color(GREEN), z(20)])

playing = True


def show(when, name, result):
    # One line of the log: a dark strip at the bottom, which moves up.
    # area() lets it know when the mouse is over it, and the dictionary
    # keeps the name it is showing, to check against the users when it is
    # clicked. The words are its children, so they move with it.
    row = add([rect(540, ROW - 2), pos(10, LOG_BOTTOM), color(8, 14, 10),
               area(), {"name": name}, "row", "line"])
    row.add([text(when, size=22), pos(10, 4), color(DIM)])
    row.add([text(name, size=22), pos(100, 4), color(GREEN)])
    if result == "failed":
        row.add([text("FAILED", size=22), pos(300, 4), color(RED)])
    else:
        row.add([text("ok", size=22), pos(300, 4), color(GREEN)])

# open in between, and remembers where it got to, so each readline()
# hands over the line after the last one.
log_file = open("log.txt", "r")


def next_line():
    global log_file

    if not playing:
        return

    line = log_file.readline()

    # At the end of the file there is nothing left, and readline() gives
    # back "". Close it, open it again, and start from the top.
    if line == "":
        log_file.close()
        log_file = open("log.txt", "r")
        row = add([rect(540, ROW - 2), pos(10, LOG_BOTTOM),
                   color(8, 14, 10), "row"])
        row.add([text("----- end of log.txt, reading it again", size=22),
                 pos(10, 4), color(DIM)])
        wait(ROW / SCROLL, next_line)
        return

    parts = line.strip().split(",")
    show(parts[0], parts[1], parts[2])

    # The next line once this one has moved up out of its way.
    wait(ROW / SCROLL, next_line)


next_line()


# Every row moves up, and one that has gone past the top is gone.
@onUpdate("row")
def move_up(row):
    if not playing:
        return
    row.pos.y = row.pos.y - SCROLL * dt()
    if row.pos.y < LOG_TOP - ROW:
        row.destroy()


# A line you can click lights up while the mouse is over it.
@onUpdate("line")
def light_up(row):
    if row.isHovering():
        row.color = rgb(25, 50, 32)
    else:
        row.color = rgb(8, 14, 10)


@onClick
def click():
    if not playing:
        return
    for row in get("line"):
        if row.isHovering():
            check(row)
            return


def check(row):
    global playing

    # A name on the list is only a name. A name that is NOT on the list
    # is somebody's password.
    if row.name in users:
        shake(6)
    else:
        playing = False
        log_file.close()
        destroyAll("row")
        message.text = "ACCESS GRANTED"
        add([text("the password was " + row.name, size=26),
             pos(280, 350), anchor("center"), color(GREEN), z(20)])
  • The slip is a line picked at random, but not one of the first four, so you have read some of the log before it comes. There the log gets two lines instead of one: a password from PASSWORDS that FAILED, then the person who typed it logging in properly a moment later.
  • Look at PASSWORDS. They are real passwords that thousands of real people use, which is why they are the first ones a hacker tries. A lot of them are names, so jordan in the log looks just like a user. The only way to tell is to check the list.
  • Each row has area(), so it knows when the mouse is over it, and {"name": name}, so it remembers the name it is showing as row.name. It has two tags. "row" is every row, so they all move up. "line" is only the rows you can click, so the end of log.txt row moves with them but can't be clicked.
  • check() is the whole game in one if. row.name in users asks whether the name is on the list read from users.txt. If it is, it is only a name. If it isn't, it is somebody's password.
  • playing stops everything once you are in: no new lines, nothing moves, and no more clicks count.

Break it. In read_users, change users.append(line.strip()) to users.append(line). The users down the right look exactly the same. Now click any line at all: ACCESS GRANTED, every time, and the password was olivia, or whoever you clicked.

Without strip() the list is ["olivia\n", "max\n", ...]. A "\n" doesn't show on the screen, so the names look right, but "olivia" is not the same string as "olivia\n". No name in the log is on the list any more, so every name is a password. This is the most common mistake there is with files, and it never makes an error message.

Step 5 — the trace

Now there is a clock you can see. The trace rises all the time, a wrong click makes it jump, and at 100% you are caught. The whole thing goes into a scene, so getting in, or getting caught, can start a new server.

  • Everything is inside @scene("server"), so go("server") starts it again from the top: new files, an empty log, the trace back at zero. After ACCESS GRANTED, wait(2, next_server) does that two seconds later.
  • The trace goes up in tracing, every frame, by TRACE_SPEED * dt(). That's 3% a second however fast the computer is. The bar is 200 pixels wide when it is full, so its width is trace * 2. int() cuts the decimals off for the label.
  • A wrong click adds WRONG_CLICK to the trace, shakes the screen and shows how much it cost, just where you clicked.
  • caught() takes the log away, shows TRACED, and waits a second before you can start again. That way a click meant for the log doesn't start a new game before you have seen what happened.
  • global: trace, playing and the others are made at the top of the program and changed inside functions, so every function that changes one says global first.

Break it. Take out the line trace = 0 inside the scene. There is no error. The first server is the same, but the second one starts with the trace where the first left off. In one run it got in at 34%, so server two started at 34%, and server three at 67%, and the trace caught it there.

trace lives outside the scene, so going to the scene again doesn't reset it. Anything that has to start again with every server has to be set again at the top of the scene.

Step 6 — the whole game

The servers get harder, there are sounds, the best score is remembered, and the first time you play, a message says what to do. This is the game you played, line for line.

  • The scene is given the server's number: def server(number), and go("server", number + 1) goes to the next one. Every setting has a _START for server 1 and a _MORE for each one after. So server 3 has USERS_START + 2 * USERS_MORE users, which is 6, a longer log, and a faster one.
  • There are twelve names, and one more user on every server, so server 10 would want thirteen different ones. The while loop in write_files could never find them. It would go round for ever, and the game would freeze. So the scene stops at len(NAMES).
  • say() puts the instructions up the first time and pauses the game until you close them. told remembers that it has been said, so it isn't said again every server.
  • The best score is the most servers you got into. setData saves it and getData reads it back, even after the page is closed.
"""Log Hacker -- somewhere in the server's log is a password. Find it.

    click the line that gives a password away

You have broken into a server and you are reading its log: one line for
every time somebody tried to log in, saying when, who, and whether it
worked. People make mistakes. Now and then somebody types their PASSWORD
into the box where their NAME should go, and the server writes it down in
the log, in plain sight.

The people who really have accounts are listed on the right. A failed
login by a name that is NOT on that list is not a name at all -- it is
somebody's password. Click it before the trace reaches 100% and you are
in. Every server is faster than the last.

HOW THIS FILE IS PUT TOGETHER

    1. the window and the sounds
    2. the names and the passwords
    3. the settings
    4. writing the server's files
    5. reading them back
    6. the game scene: the log going past, clicking, the trace
    7. start the game

This is the game for files. A real hacker would find the files already
on the server. This game has to make its own first, with open("users.txt",

# ------------------------------------------------ 4. writing the server's files
#
# Two files. users.txt has one name on each line:
#
#     ada
#     zoe
#
# and log.txt has one login on each line, its three parts with commas
# between them -- when, who, and whether it worked:
#
#     01:07,zoe,ok
#     01:12,ada,failed
#
# "\n" is the end of a line. write() does not add one for you, so without
# it every name would end up on the same line: adazoemaxsam.

def two_digits(number):
    if number < 10:
        return "0" + str(number)
    return str(number)


def clock(minutes):
    # 75 minutes after midnight is 01:15. // is how many whole hours, and
    # % is the minutes left over.
    hours = minutes // 60 % 24
    return two_digits(hours) + ":" + two_digits(minutes % 60)


def write_files(how_many_users, how_many_lines):
    # Pick the users. A name that is already picked is skipped, so the
    # loop goes round until there are enough different ones.
    users = []
    while len(users) < how_many_users:
        name = choose(NAMES)
        if name not in users:
            users.append(name)

    users_file = open("users.txt", "w")
    for name in users:
        users_file.write(name + "\n")
    users_file.close()

    # The line where somebody slips up. Not one of the first few, so you
    # have read a little of the log before it comes.
    slip = randi(4, how_many_lines - 1)

    log_file = open("log.txt", "w")
    minutes = randi(0, 300)
    for number in range(how_many_lines):
        minutes = minutes + randi(1, 9)
        when = clock(minutes)

        if number == slip:
            # A password where the name should be, which fails -- and then
            # the same person, a moment later, getting it right.
            victim = choose(users)
            log_file.write(when + "," + choose(PASSWORDS) + ",failed\n")
            log_file.write(when + "," + victim + ",ok\n")
        else:
            name = choose(users)
            if chance(FAIL_CHANCE):
                result = "failed"
            else:
                result = "ok"
            log_file.write(when + "," + name + "," + result + "\n")

    log_file.close()


# --------------------------------------------------- 5. reading them back
#
# users.txt is read all at once, with a for loop: each time round, line is
# the next line of the file. Every line ends in its "\n", and strip()
# takes it off -- without that, "ada\n" is not "ada", and nobody would
# ever be on the list.

def read_users():
    users = []
    users_file = open("users.txt", "r")
    for line in users_file:
        users.append(line.strip())
    users_file.close()
    return users
